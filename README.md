# pi-happ

[English version](README.en.md)

Неофициальный порт минимальной функциональности Happ в pi: управление подписками, выбор VPN-локации и проверка внешнего IP прямо в TUI. Это не полный перенос приложения Happ: расширение самостоятельно запускает Xray дочерним процессом, без TUN и системного VPN.

Linux, Node.js 22.19+, pi 1.6.0.

## Статус: разрабатываемое расширение

Реализованы:
- TUI-команда `/happ`: добавление, обновление, удаление подписок и выбор локации;
- импорт HTTPS-подписки в формате массива Xray JSON;
- дочерний Xray без TUN, sudo, happd и системного прокси;
- проверка внешнего IP через `https://icanhazip.com`, строго через локальный HTTP-прокси;
- остановка Xray при штатном завершении сессии, `/reload` и смене сессии;
- приватное локальное хранилище подписок.

OpenAI, Anthropic и Codex зарегистрированы со штатными каталогами и авторизацией, но защищённым транспортом. По умолчанию запросы блокируются, пока не подключена локация. В VPN-режиме используется HTTP/SSE, включая Codex; WebSocket принудительно отключён. Остановка/смена соединения отменяет запросы и уничтожает пул соединений. Прямой режим включается только с подтверждением в `/happ` и не сохраняется между сессиями.

OAuth login/refresh перехватывается через AsyncLocalStorage-scoped обёртку global fetch: только асинхронная работа этих провайдеров направляется через прокси, остальные fetch не меняются. Переменные окружения и системные настройки сети не изменяются. Внешний браузер не охвачен; localhost callback остаётся локальным. Это не сетевая песочница: другие провайдеры, пользовательские инструменты и произвольные сетевые библиотеки не защищены.

**Сквозные проверки реальных аккаунтов OpenAI/Anthropic и OAuth ещё не выполнены.** Не считать расширение полностью проверенной защитой от утечек.

## Запуск

На чистом Linux VPS достаточно Node.js 22.19+ и pi. Happ, curl, unzip, root и системные сервисы не нужны.

Из каталога репозитория:

```sh
npm ci --legacy-peer-deps
pi -e ./src/extension.ts
```

Добавьте подписку и выберите локацию в `/happ`. При первом подключении расширение скачает официальный Xray **26.11.9** (Linux x64/arm64), проверит закреплённый в коде SHA-256 архива и установит только бинарник в `~/.local/share/pi-happ/runtimes/`. Последующие подключения используют локальный кеш с проверкой хеша бинарника. Загрузка требует доступа к GitHub до подключения VPN.

Можно подготовить ядро заранее командой `/happ-runtime-install` — VPN при этом не запускается. Установка атомарная; повреждённый архив не исполняется. Автоустановка не запускается при загрузке расширения.

Обновление ядра привязано к версии расширения: меняются версия и SHA-256 в `src/runtime.mjs`; произвольный `latest` никогда не скачивается. Для офлайн-установки или другой Linux-архитектуры используйте собственный бинарник через `PI_HAPP_XRAY` (его происхождение и целостность проверяет пользователь). Повреждённый каталог версии в кеше нужно удалить и повторить установку.

Команда `/happ-ip-check` проверяет внешний IP через активный туннель на `icanhazip.com`, без открытия меню. Показывает IP, локацию, длительность HTTPS-запроса в миллисекундах (включая соединение/TLS и получение ответа; не ICMP-пинг) и время проверки; без подключённого VPN возвращает ошибку, не обращаясь напрямую.

Затем `/happ` → «Добавить подписку». Вводите секретный URL в диалоге, не в чате с моделью. Для другой установки ядра:

```sh
PI_HAPP_XRAY=/path/to/xray pi -e ./src/extension.ts
```

Для постоянной установки пакета: `pi install /absolute/path/to/pi-happ`.

## Отмена и диагностика

Во время установки ядра, загрузки подписки и подключения TUI показывает отменяемый индикатор: нажмите Esc. Отмена соединения завершает Xray/watchdog и удаляет временный конфиг; интерфейс ждёт окончания очистки. В RPC-режиме тот же сигнал отменяется при завершении сессии (интерактивный Esc — только в TUI).

`/happ-diagnostics` показывает состояние и последнюю распознанную категорию ошибки ядра. Сырые сообщения Xray не отображаются и не пишутся в файл: они могут содержать ключи и адреса. Распознаются ошибки конфигурации, порта, прав, DNS, TLS/Reality и недоступности VPN-сервера. Диагностика ограничена известными шаблонами, отсутствие категории не означает отсутствие ошибки.

## Headless OAuth на VPS

Сначала подключите локацию в `/happ`, затем `/login`:
- OpenAI Codex → **Device code login (headless)**: открыть ссылку на своём компьютере, подтвердить код;
- Anthropic → **Copy code login (headless)**: открыть ссылку на своём компьютере, вставить полученный код в диалог pi.

Браузер на VPS и SSH callback-туннель для этих способов не нужны. Сетевой обмен токенами и refresh на VPS проходит через дочерний Xray; браузер на компьютере через него автоматически не идёт. Коды и токены не вставляйте в чат модели. Проверка с реальными аккаунтами остаётся ручной.

## Ограничения и безопасность

- Подписки хранятся в `~/.config/pi-happ/subscriptions.json` (файл 0600, новый каталог 0700). Это секреты в открытом виде: не публикуйте и не коммитьте их.
- URL подписки и содержимое не добавляются расширением в сообщения/сессию pi.
- Загрузка подписок сейчас прямая, с таймаутом 25 секунд, без редиректов, лимит 4 MiB. Только JSON-массив; URI/Base64, YAML и happ:// пока не поддержаны.
- Вход в профиль — первый поддерживаемый proxy outbound; сохраняются все достижимые зависимости `proxySettings.tag` и `streamSettings.sockopt.dialerProxy`. Проверяются отсутствующие/повторяющиеся теги, циклы и ссылки на direct/неподдерживаемые outbounds. Исходные listeners, routing, DNS и API не запускаются. Balancers, интерфейсные привязки и произвольные правила маршрутизации не поддерживаются.
- Поддержка протокола зависит от установленного Xray. Ошибка запуска/проверки IP не вызывает прямого fallback.
- Локальный прокси слушает только 127.0.0.1 на случайном порту, без аутентификации (доступен другим локальным процессам).
- Xray проверяется запросом внешнего IP перед объявлением готовности. Запуск может занимать до ~40 секунд плюс первая загрузка ядра (таймаут 120 секунд, архив до 80 MiB).
- На Linux Xray остаётся непосредственным дочерним процессом pi. Отдельный Node.js watchdog следит за приватным pipe: при смерти pi (в том числе SIGKILL) pipe закрывается, watchdog посылает Xray SIGTERM, через 2 секунды — SIGKILL, затем удаляет временный конфиг. Проверка PID + `/proc` starttime защищает от переиспользования PID. Если watchdog неожиданно завершается, живой pi останавливает Xray и инвалидирует транспорт.
- Watchdog работает только на Linux с доступным `/proc`. Это userspace-защита: есть короткое окно между запуском Xray и готовностью watchdog. Одновременный SIGKILL обоих процессов также не покрывается. Для абсолютной гарантии потребовался бы Linux parent-death signal через нативный launcher. Подключение не объявляется готовым до запуска watchdog.
- Используйте только доверенные подписки. Полная проверка вложенных outbound-настроек и сетевых адресов ещё не реализована.
- Автоматический запуск/подключение и изменение сетевых настроек при загрузке расширения отсутствуют.

## Разработка

```sh
npm test
npm run check
```

После клонирования выполните `npm ci --legacy-peer-deps` для установки undici (транспорт HTTP CONNECT) и fflate (распаковка проверенного ZIP без внешних утилит).

Тесты офлайн, с синтетическими профилями и локальным CONNECT-прокси: проверяются маршрутизация, scoped OAuth fetch, отмена сигнала и отсутствие прямого fallback после отказа прокси. Тесты watchdog запускают синтетический Xray отдельным процессом: проверяются SIGKILL родителя, эскалация для процесса, игнорирующего SIGTERM, авария watchdog и штатная остановка, включая удаление конфигов. Реальные подписки и аккаунты в тестах не используются. Загрузка расширения проверена командой `pi -e ./src/extension.ts --list-models openai`. `npm run check` проверяет TypeScript-точку входа с API pi и синтаксис JS-модулей (глубокая проверка `checkJs` пока выключена). CI запускает типизацию и тесты на Node.js 22/24. Отдельные тесты используют настоящие адаптеры OpenAI, Anthropic и Codex с локальным mock-сервером: проверяют CONNECT, успешный текстовый SSE-ответ, обработку ошибки API и прерывание SSE при смене VPN. Также проверяются отмена активного подключения с очисткой процессов и валидация цепочек. Полный TUI и реальные OAuth-аккаунты ещё не покрыты автоматическими тестами.
